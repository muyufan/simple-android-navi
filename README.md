# Android Navi

Android Studio-like code navigation for Android Gradle projects in VS Code. It gives
`redhat.java` (Eclipse JDT LS) the classpath AGP actually compiles with, so Ctrl-click lands on
the real source of a sibling module instead of decompiled bytecode, and `android.*` resolves into
the platform jar.

## Requirements

- VS Code 1.85 or newer.
- [Language Support for Java(TM) by Red Hat](https://marketplace.visualstudio.com/items?itemName=redhat.java)
  (`redhat.java`). It is a declared dependency, so VS Code offers to install it.
- A Gradle wrapper (`gradlew` / `gradlew.bat`) in the project root.
- A working Android build: JDK, Android SDK (`ANDROID_HOME` or `local.properties`), and network
  access for Gradle dependencies on the first run.

## Install without the Marketplace

The extension is not published (`"publisher": "local"`). Share the packaged VSIX:

```bash
npm install
npm run package:vsix        # -> android-navi-0.1.0.vsix
```

Then, on the other machine:

1. Extensions view → `...` menu → **Install from VSIX…**, or from a terminal:

   ```bash
   code --install-extension android-navi-0.1.0.vsix
   ```

2. Install `redhat.java` as well if the machine cannot reach the Marketplace (download its VSIX on
   a connected machine and install it the same way).
3. Reload the window and open the Android project folder.

To update, bump `version` in `package.json`, re-run `npm run package:vsix`, and install the new
VSIX over the old one.

### Publishing instead of sharing a file

- **Open VSX** (VSCodium, Cursor, Gitpod): create a publisher on <https://open-vsx.org> and run
  `npx ovsx publish android-navi-0.1.0.vsix -p <token>`.
- **VS Code Marketplace**: change `publisher` in `package.json` to your Marketplace publisher id,
  create an Azure DevOps PAT, then `npx vsce publish -p <token>`.

## What it does when a project is opened

1. Applies `java.import.gradle.enabled=false`, `java.import.maven.enabled=false` and
   `java.configuration.updateBuildConfiguration=disabled` at workspace scope
   (`.vscode/settings.json`, or the `.code-workspace` file). JDT LS is one server per window, so
   these settings cannot be folder scoped.
2. Runs
   `./gradlew --init-script <extension>/gradle/android-navi-model.gradle --no-configuration-cache androidNaviModel`.
   The task compiles the selected variant, because `R.jar`, `BuildConfig` and sibling
   `classes.jar` only exist after that.
3. Writes a `.project` and `.classpath` per module (marked "generated by android-navi"), adds them
   to `.git/info/exclude`, and asks JDT LS to re-read the classpaths.
4. On the first sync, if Java still holds projects imported by its Gradle importer, it offers
   **"Clean Java workspace and reload"** — that reload is what makes navigation fully correct.

The first sync compiles the variant, so it can take minutes. The status bar shows elapsed time and
the current Gradle task; click it to cancel. The log is in **Output → Android Navi**.

## Commands

| Command | Purpose |
| --- | --- |
| `Android Navi: Sync Android Classpath` | Re-run the Gradle model dump and rewrite `.project`/`.classpath`. |
| `Android Navi: Cancel Sync` | Stop a running sync (also: click the status bar while syncing). |
| `Android Navi: Reload Java Model (restart JDT LS)` | Re-apply the model from disk and restart the Java language server. |
| `Android Navi: Show Output` | Open the Android Navi output channel. |
| `Android Navi: Restore Java Settings (before uninstalling)` | Revert the `java.*` settings the extension changed. |

## Settings

| Setting | Default | Meaning |
| --- | --- | --- |
| `androidNavi.variant` | `debug` | Variant to model; it must exist in every module. |
| `androidNavi.extraGradleArgs` | `[]` | Extra arguments appended to the Gradle invocation, e.g. `["-x", ":app:downloadBootstraps"]`. |
| `androidNavi.syncOnStartup` | `true` | Sync when a workspace folder is opened. |
| `androidNavi.gradleTimeoutMinutes` | `20` | Stop a sync that runs longer than this (0 = no limit). |

## Files it touches in your project

- `.project`, `.classpath` in each Android module (regenerated on every sync; listed in
  `.git/info/exclude`).
- `build/android-navi-model.json` (the raw model).
- `.vscode/settings.json` (workspace-scoped `java.*` settings above).

## Uninstalling

Run **Android Navi: Restore Java Settings** first, then uninstall. The workspace setting is kept on
purpose between sessions: JDT LS reads it at startup, and removing it on every window close let the
Gradle importer reclaim the workspace before the extension could re-apply it.
